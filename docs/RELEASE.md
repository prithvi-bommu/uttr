# Release Runbook

## Automated releases (GitHub Actions)

`.github/workflows/release.yml` publishes DMGs automatically:

- **Every merge to `main`** rebuilds the DMG and updates the rolling
  **"latest"** prerelease — the newest build is always downloadable from
  the repo's Releases page (public downloads require the repo to be public).
- **Pushing a version tag** (`git tag v1.0.0 && git push origin v1.0.0`)
  creates a permanent versioned release with generated notes.

CI imports the stable self-signed Uttr release certificate, signs the app with
a timestamp and hardened runtime, and verifies the complete code-signature
tree. The workflow fails before publication when the signing certificate or
Sparkle key is missing or invalid. This avoids requiring Apple Developer
enrollment; each new Mac needs a one-time right-click → Open confirmation.

Each release ships the `.dmg` plus a `.sha256` checksum file.

## Code Signing (read first)

`Scripts/release-dmg.sh` auto-detects the signing identity, in priority order:

| Priority | Identity | When |
|---|---|---|
| 1 | `$UTTR_SIGN_IDENTITY` env var | Explicit override |
| 2 | `Developer ID Application: …` | Optional local identity |
| 3 | `Uttr Dev Signing` (self-signed) | Interim local builds — keeps TCC grants stable across rebuilds on the dev machine (ADR-010) |
| 4 | Ad-hoc (`-`) | Fallback — permission grants reset on every rebuild |

For local development, `release-dmg.sh` uses a Developer ID identity when one
is installed, otherwise the self-signed development identity or ad-hoc
fallback. Local DMGs are never part of the Sparkle update channel.

Recreating the self-signed cert on a new machine (ADR-010): create a
code-signing cert named `Uttr Dev Signing` via Keychain Access → Certificate
Assistant (or openssl with `-legacy` PKCS12 export), import into the login
keychain, then `security add-trusted-cert -p codeSign -k
~/Library/Keychains/login.keychain-db cert.pem`.

## Auto-updates (Sparkle)

Uttr uses [Sparkle](https://sparkle-project.org/) (v2.9.5) for over-the-air updates.

The production channel uses a stable self-signed certificate, not Developer ID or notarization. This is intentional so the project can distribute updates without Apple Developer enrollment.

**How it works:**
- The release workflow builds, Developer ID-signs, notarizes, and staples a DMG. It then signs those final DMG bytes with the Sparkle EdDSA key, generates an `appcast.xml`, and publishes it to GitHub Pages at `https://prithvi-bommu.github.io/uttr/appcast.xml`.
- `SUFeedURL` in `Info.plist` points at this URL.
- Sparkle checks the appcast, compares `sparkle:version` (which equals `CFBundleVersion`, stamped from `github.run_number`) against the installed build, and offers updates when a newer build is available.
- The appcast is also uploaded as a release asset for debuggability.

**Required GitHub configuration:**

- Secret `UTTR_SIGNING_CERTIFICATE_P12_BASE64` — base64 of the stable self-signed `Uttr Release Signing` certificate and private key.
- Secret `UTTR_SIGNING_CERTIFICATE_P12_PASSWORD` — password used to export that `.p12`.
- Secret `SPARKLE_PRIVATE_KEY` — the existing EdDSA private key generated by Sparkle's `generate_keys` tool.

Create the stable certificate once on a trusted Mac:

```bash
./Scripts/create-release-signing-cert.sh
```

Keep the generated `.p12` and password in a secure backup. Add the base64
contents of the `.p12` and its password to the two GitHub secrets above.

The workflow verifies the generated archive signature against the exact
`SUPublicEDKey` embedded in the app before it publishes the appcast. Preserve
both private keys; rotating either breaks updates for installed versions.

**⚠️ Critical:** If the private key is lost, every already-installed copy of Uttr becomes permanently un-updatable. They only trust the public key baked into their bundle (`SUPublicEDKey` in `Info.plist`), and the only recovery is manually reinstalling from a DMG. Back the key up somewhere safe outside the repo.

**Migration note:** distribute the first stable-signed DMG as a one-time manual
install if an existing ad-hoc installation cannot validate the transition.
Every subsequent release uses the same certificate and Sparkle keys and
updates normally. This is not notarized, so users may need the initial
right-click → Open approval on each Mac.

## Prerequisites (official external release)

- GitHub release secrets listed above
- Clean working tree on `main`
- All tests passing

## Steps

1. **Verify clean state**
   ```bash
   git status
   ./Scripts/test.sh
   ```

2. **Update version**
   - Set `MARKETING_VERSION` in Xcode project
   - Increment `CURRENT_PROJECT_VERSION`
   - Update `CHANGELOG.md`: move Unreleased items under new version heading

3. **Tag the release**
   ```bash
   git tag -a v1.0.0 -m "Release v1.0.0"
   git push origin v1.0.0
   ```

4. **Archive**
   ```bash
   ./Scripts/archive.sh
   ```

5. **Notarize**
   ```bash
   ./Scripts/notarize.sh build/export/Uttr.app
   ```

6. **Create DMG**
   ```bash
   ./Scripts/make-dmg.sh build/export/Uttr.app 1.0.0
   ```

7. **Verify Gatekeeper**
   ```bash
   spctl --assess --type execute --verbose build/export/Uttr.app
   ```

8. **Publish GitHub Release**
   ```bash
   gh release create v1.0.0 build/Uttr-1.0.0.dmg \
       --title "Uttr v1.0.0" \
       --notes-file CHANGELOG.md
   ```

9. **Verify on clean machine**
   - Download DMG from GitHub Release
   - Drag to Applications
   - Launch and verify Gatekeeper does not block
   - Run basic dictation test
